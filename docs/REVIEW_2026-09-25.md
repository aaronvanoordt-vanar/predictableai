### 2.1 Exposición del repositorio y del sitio

- **`_config.yml`** (nuevo): GitHub Pages sirve `main` desde la raíz; Jekyll solo excluía lo que empieza por `_` o `.`. La auditoría del 2026-07-02 ya lo había borrado; volvió con el commit #203. ## 4. Sobre el pedido "que nadie pueda copiar el código"

Lo honesto primero: **el repositorio es público** (`aaronvanoordt-vanar/predictableai`, comprobado con la API de GitHub) y GitHub Pages servía el backend desde el dominio de producción. Cualquiera —persona o IA— podía clonar los prompts, la lógica del motor, las políticas RLS y los márgenes. Con este PR:

- Lo que **sí** queda protegido: el backend deja de servirse desde el dominio; el `LICENSE` niega cualquier licencia de uso y reproducción (deterrente legal, y base para un DMCA); las claves siguen solo en secrets de Supabase.
- Lo que **solo tú puedes hacer**: **poner el repositorio en privado** (Settings → General → Danger Zone → Change visibility). GitHub Pages sigue funcionando desde un repo privado con un plan GitHub Pro/Team/Enterprise. Mientras sea público, todo el backend está a un `git clone` de distancia y esta migración a "privado" es la única medida que de verdad cierra esa puerta.
- Lo que **no es posible**: impedir que se copie el JavaScript que el navegador ejecuta. Minificar u ofuscar `js/` eleva el costo para una persona, pero una IA lo desofusca en segundos, obligaría a introducir un paso de build (la arquitectura del proyecto es "sin build" a propósito) y rompería la verificación de `scripts/check.mjs`. **No se hizo.** El valor defendible está en el servidor (prompts, motor, aprendizaje, datos, integraciones), y eso es lo que el repo privado + `_config.yml` protegen.
- El dominio real de la ventaja no está en el código: está en la base de conocimiento por cuenta, el bucle de aprendizaje, las cuentas conectadas y los datos. Nada de eso viaja con un clon.
